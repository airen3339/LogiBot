# LogiBot
行业里 ChatBot 很多，但大多数只能"陪聊"。LogiBot 是一套能直接"办业务"的智能客服系统：覆盖运单查询 / 运费计算 / 时效查询 / 网点查询 / 政策咨询 / 工单流转 / 人机协同 / 微信公众号 / 企业微信 9 条主链路。受控 Agent 架构，LLM 只做理解，路由与执行由状态机+责任链+策略完成，行为可测、可控、可审计。

## 一、产品定位

logibot 是一套面向**快递/物流企业的智能客服系统**。它把"运单查询、网点查询、运费时效、政策问答、转人工、工单、数据监控"等高频客服动作整合到一个统一的对话入口（Web、公众号、企业微信），通过**受控 Agent（state machine + LLM）**让 AI 直接理解并执行客服任务，让人工坐席只处理例外情况。

核心价值：

- 降低客服人力 50%+（运单、网点、运费、政策类问题机器全自动办理）
- 提升首响速度至 1 秒内（无须坐席打字转述）
- 全量会话可检索、可标注、可复盘，形成**客服知识库闭环**
- 对外提供公众号 / 企微 / Web 三端一致体验

## 二、模块与能力清单

logibot 由 10 个 Maven 模块组成，遵循"业务能力下沉 / 渠道与编排上浮"的架构：

| 模块 | 角色 | 关键能力 |
|:---|:---|:---|
| logibot-common | 公共工具与基础抽象 | 异常总线、统一响应、监控计数、对象存储、本地缓存 |
| logibot-system | 配置中心与基础设施 | 启动配置、Profile 切换、Bean 注册条件 |
| logibot-llm | 大模型适配层 | Prompt 模板、LLM Provider、Token 计量、重试 |
| logibot-rag | 知识库与检索 | 文档解析、分块、向量化（应用层）、混合检索（RRF） |
| logibot-business | 业务原子能力 | 运单查询、运费测算、时效查询、网点查询、政策查询 |
| logibot-agent | 受控 Agent | 意图识别、状态机、Flow、责任链、会话管理 |
| logibot-channel | 渠道适配 | Web Chat、微信公众号、企业微信回调 |
| logibot-admin | 运营后台 | 工单、人机协同、会话审计、数据看板、灰度、告警 |
| logibot-server | 启动装配 | SpringBoot 启动、Actuator、统一打包 |
| logibot | 顶层 Reactor | 9 个子模块聚合、统一版本 |

## 三、面向客户的核心能力

### 3.1 运单查询与轨迹（覆盖基础流程）

客户问"我的快递到哪了"，logibot 自动解析运单号，调用 TrackLog API，回复当前状态 + 最近 5 条轨迹 + 下一站预估，并以**运单卡片**呈现（支持链接到详细轨迹）。

### 3.2 网点查询

客户问"我在 XX 城市有自提点吗？"，logibot：

- 自动归一化城市别名（"帝都→北京"、"沪→上海"、"魔都→上海"）
- 按区域过滤（"朝阳、浦东"），排除中转场
- 按服务项过滤（"自提、上门、派送"）
- 推送**网点卡片**（含电话、地址、营业时间、服务项）

### 3.3 运费与时效

客户问"20 公斤从北京到上海多少钱？几天到？"，logibot：

- 自动识别重量（"kg/公斤/斤/磅"）、体积（cm/cm³）、体积重
- 区域路由（同城 / 跨省 / 偏远统一价 / 距离分档兜底）
- 反向区域对复用（"上海→北京"等价于"北京→上海"）
- 服务类型归一化（"标准、特快、经济、SF" 等）
- 推送**运费卡片**（含首重、续重、计费重量、合计、附加费）+ **时效卡片**

### 3.4 政策问答（FAQ + 文档）

客户问"锂电池能寄吗？""液体能寄吗？"，logibot：

- 用 RAG 检索 FAQ（50 条）和 5 篇知识文档（200+ 分块）
- 命中 FAQ 直接给出标准答案并标注来源
- 命中知识文档，摘录片段作答并标注出处
- 相似度低于阈值或关键词重合度过低，**自动转人工**（不强行编造答案）

### 3.5 多轮对话与槽位

logibot 在用户未给出完整信息时**追问而非报错**，例如：

> 用户：上海到北京 20 公斤多少钱
> 机器人：好的，从上海到北京 20 公斤，标准件运费约 XX 元，3~4 天送达。是否需要上门取件？

槽位（始发地、目的地、重量、服务类型）会写回会话上下文，下次用户说"特快呢？"会自动继承并重算。

### 3.6 转人工与排队

当用户表达"我要投诉/举报""转人工"，或机器判定置信度不足、连续 2 轮未识别、命中高风险场景时，logibot：

1. **自动建单**（投诉 P1 / 建议 P4；异常件按丢件 P1、破损·延误 P2），工单摘要走 AI，LLM 不可用时自动降级为规则摘要
2. 加入人工队列（先到先服务，`t_human_transfer` 按入队时间升序）
3. 队列超时（默认 3 分钟未接入）→ 自动回复留言话术，提示可直接留言或继续向机器人提问
4. 坐席接入时展示**交接摘要**（渠道、最近意图、已知运单号与脱敏手机号、最近 8 轮对话），并附 6 条一键快捷话术

> 异常件与投诉走两条独立工作流（`AbnormalFlow` / `ComplaintFlow`）：先核实轨迹/记录诉求，再建单并转人工；
> 即使建单失败，转人工兜底依然生效，用户始终能得到人工协助。

### 3.7 工单与流转

工单四态：OPEN（待受理）→ PROCESSING（处理中）→ PENDING_CONFIRM（待客户确认）→ CLOSED（已结单）。
工单支持：

- **自动创建**（会话中途由异常件/投诉工作流触发，或坐席一键建单；AI 摘要 + 手机号 AES 加密）
- **分级**（P1 紧急 / P2 高 / P3 中 / P4 低，按类型自动判定：丢件·投诉 P1，破损·延误 P2，建议 P4）
- **SLA 计时**（P1 2 小时、P2 8 小时、P3 24 小时、P4 72 小时；重开时按当前时间重新计时）
- **流转**（派单/转派、回复、待客户确认、结单、重开）
- **打印**（工单详情页一键打印，含流转记录与会话摘录）

### 3.8 数据看板（运营）

6 张指标卡 + 3 张图表：

- 指标卡：今日会话、人工转接率、平均 CSAT、机器解决率、平均响应时间、SLA 达成率
- 趋势图：近 7 天会话量与机器解决率
- 意图分布：TOP 10 意图占比
- 热点问题：检索命中 TOP 10

### 3.9 监控告警（运维）

- 错误计数（按模块、错误码）
- LLM Token 用量（日维度，防爆预算）
- 外部 API 调用（P95 延迟、错误率）
- JVM 指标（Micrometer）
- 告警规则：SLA 超时 / 预算 80% / 服务异常 / 钉钉机器人触达

### 3.10 灰度发布

对核心 Flow 可按会话哈希取模开启 10% 流量灰度，配合错误计数与人工评分，无回归则逐步放量。

## 五、依赖与外部对接

logibot 通过**适配器接口 + Mock 实现**与外部解耦，便于联调与替换：

| 外部依赖 | 适配器接口 | 当前实现 | 生产替换 |
|:---|:---|:---|:---|
| 运单轨迹 API | TrackLogApi | MockTrackLogApi | 对接快递公司 |
| 运费 API | FeeCalcApi | MockFeeCalcApi | 对接计费系统 |
| 时效 API | EtaQueryApi | MockEtaQueryApi | 对接路由系统 |
| 网点 API | BranchQueryApi | MockBranchQueryApi | 对接网点系统 |
| LLM | LlmClient | 内置（可切换） | 替换真实 Key |
| 微信公众号 | WechatMpController | 原生 XML 验签 | 填入真实 Token |
| 企业微信 | WecomController | 原生 XML 验签 | 填入真实 Token |
| 钉钉机器人 | AlertService | 内置 Mock | 填入 Webhook |

## 六、术语表

| 术语 | 含义 |
|:---|:---|
| 受控 Agent | LLM 只做理解，路由/执行由状态机+策略+责任链完成 |
| Flow | 一个完整业务流的处理逻辑（如 FeeCalcFlow、EtaQueryFlow） |
| Slot | 多轮对话中需要从用户输入抽取并持久化的字段 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| RRF | Reciprocal Rank Fusion，多路召回结果的倒数排名融合 |
| 灰度发布 | 按比例放量的发布方式（默认 10%） |
| SLA | Service-Level Agreement，服务等级协议 |
| CSAT | Customer Satisfaction Score，客户满意度评分 |
